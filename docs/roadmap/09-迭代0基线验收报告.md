### ⚠️ 关键修复：原 `.gitignore` 有安全缺陷

仓库里已存在一个 `.gitignore`，但**不覆盖 `.env.production-do-not-use`**：

```gitignore
# 原文件（有缺陷）
.env          ← 只精确匹配 ".env" 这个文件名
```

`.env.production-do-not-use` 里存放**生产环境的 JWT_SECRET / ENCRYPTION_KEY / DB 密码**。
按原规则它会被 `git add -A` 一起提交，一旦推送到远端就是密钥泄漏。

**已修复为显式排除**：

```gitignore
.env.production-do-not-use
.env
.env.*
!.env.example
backend/.env
backend/.env.dev
backend/.env.local
backend/.env.production*
```

### ⚠️ 过程中发现并解决的一个问题

**首轮 e2e 出现 3 项失败**：

```
❌ 建货源自动预填库存 (stock=0)
❌ 建货源自动预填成本价 (cost_price=0)
❌ 预填同时记录同步时间 (stock_synced_at=null)
```

**根因**：本地 `backend/.env` 显式设置了 `UPSTREAM_VERIFY_SUPPLY=false`，
而代码默认值是 `true`（`config.go: envBool("UPSTREAM_VERIFY_SUPPLY", true)`），
e2e 脚本按默认值 `true` 编写断言。

**这不是代码缺陷，是本地配置与验收预期不一致。**

**处置**：将 `backend/.env` 改为 `UPSTREAM_VERIFY_SUPPLY=true`，重启后端后重跑 → **74/74 全通过**。

> 注意：`backend/.env` 已被 gitignore，此改动**不会进入版本库**，只影响本机。
